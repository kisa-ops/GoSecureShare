Installation Guide

Step-by-step instructions to install GoSecureShare on your server. Covers prerequisites, the interactive install prompts, and SSL setup. Estimated time: 15–30 minutes.

Prerequisites

Ensure the following are in place before running the installer. The script auto-installs Docker, Docker Compose, and Nginx as needed, but some items must be prepared in advance.

  • Linux server — Ubuntu 20.04+, Debian 11+, or Rocky / RHEL 8+. Root or sudo access required.
  • Internet access — The server must reach ghcr.io, raw.githubusercontent.com, and Docker Hub to pull images and lib files.
  • GitHub PAT with read:packages scope — Required to pull images from GHCR. Generate at github.com/settings/tokens. Classic or fine-grained token both work.
  • Two DNS records pointing to the server — e.g. platform.example.com (admin UI) and share.example.com (recipient link). Required if using SSL.
  • TLS certificates (optional, SSL Mode 2 only) — If not using your own reverse proxy, have your certificate, private key, and CA bundle files ready on the server (or be prepared to paste PEM content).
  • Ports 80 / 443 available — Ensure no existing web server is holding these ports if you plan to use SSL Mode 2 (host Nginx mode). Run ss -tlnp | grep ':443' to check.
HTTPS is required for browser encryption GoSecureShare uses the Web Crypto API for zero-knowledge encryption. This API only works over HTTPS. If you skip SSL setup during install, encryption will be broken until HTTPS is configured.
2

Download & Run install.sh

The installer is self-bootstrapping — it only needs itself. It will fetch all required library files automatically from GitHub before installation proceeds.

Option A — Download and run in one step

# Download the installer
curl -fsSL https://raw.githubusercontent.com/kisa-ops/GoSecureShare/main/install.sh \
  -o install.sh

# Make it executable and run as root
chmod +x install.sh
sudo ./install.sh

Option B — Pin to a specific version

GSS_VERSION=2.3.1 sudo ./install.sh

By default the installer auto-detects and installs the latest stable release. Use GSS_VERSION to pin to a specific version if required.

Self-bootstrapping If the lib/ directory is not present alongside install.sh, it will be fetched automatically from GitHub using your GHCR credentials. No additional files need to be downloaded manually.
3

GHCR Credentials

The first interactive prompts collect your GitHub credentials to pull container images from GHCR. These are asked before any other configuration.

Prompt What to Enter Notes
Your GitHub username (GHCR_USERNAME) your-github-username Any valid GitHub username. The PAT controls access, not the username. Cannot be empty.
GitHub PAT with read:packages scope (GHCR_TOKEN) ghp_xxxxxxxxxxxx Typed silently (no echo). Must have read:packages scope. Generate at github.com/settings/tokens. Cannot be empty.
Why is this required? GoSecureShare container images are hosted on GitHub Container Registry (GHCR) as a private package. The PAT is used both to fetch lib files during bootstrap and to authenticate Docker image pulls. It is stored only in the Docker credential store on the server.
4

Ports & Admin Credentials

After GHCR credentials, the script prompts for HTTP ports and the initial admin account. These settings are written to /opt/gosecureshare/.env.

Prompt Default Recommended Response
Platform HTTP portoptional 8181 Press Enter to accept default. This is the internal port for the admin UI. In SSL Mode 2 it is used as the Docker-internal port only (not exposed externally).
Recipient HTTP portoptional 80 Press Enter to accept default. In SSL Mode 2 this is overridden to 8282 internally. In proxy mode it is the port your reverse proxy forwards to.
Admin emailoptional admin@gosecureshare.local Enter your real admin email. Used to log in to the platform UI. Defaults to a placeholder — change it.
Admin passwordrequired — Minimum 12 characters. No echo. Choose a strong password — this is the only admin account created at install time.
Port note for SSL Mode 2 If you choose SSL Mode 2 (provide certificate files) in the next step, the installer overrides the HTTP ports to internal values (8181 / 8282). The ports you enter here are only used in proxy mode or HTTP-only mode.
5

SSL / HTTPS Setup

The installer asks whether to configure HTTPS now. Choosing yes (recommended) reveals the SSL mode selector.

PromptDefaultResponse
Set up HTTPS with TLS certificates now? yes Enter yes or press Enter. Entering no runs in HTTP-only mode — encryption will not work.

If you answer yes, choose one of two SSL modes:

Mode 1 — recommended

Own reverse proxy

Cloudflare, Nginx, HAProxy, F5, etc. GoSecureShare binds to 127.0.0.1 only. Your proxy handles TLS — no cert files needed here.

Mode 2

Provide certificate files

Host Nginx is installed as TLS terminator. Recipient → port 443, Platform → port 8443. Cert files (or PEM paste) required.

PromptDefaultResponse
Enter 1 or 2 (SSL mode) 1 Enter 1 for own proxy, 2 to provide cert files. Press Enter to accept Mode 1.
Platform domainrequired — e.g. platform.example.com. Must be different from the Recipient domain.
Recipient domainrequired — e.g. share.example.com. This is the public-facing URL used in secret share links.

Mode 1 — After entering domains

The installer prints the proxy target addresses. Configure your reverse proxy to forward traffic to these addresses and add the required headers:

# Target addresses printed by the installer:
https://platform.example.com  →  http://127.0.0.1:8181
https://share.example.com     →  http://127.0.0.1:80

# Required proxy headers:
X-Forwarded-Proto: https
X-Forwarded-For:   <client-ip>
Host:              <domain>
6

Certificate Files (SSL Mode 2 only)

If you chose Mode 2, the installer asks for TLS certificates for Platform and then Recipient. For each service you choose whether to provide file paths or paste PEM content directly.

PromptDefaultResponse
Platform HTTPS port 8443 Press Enter for default. Must be ≥ 1024, ≤ 65535, and not 443. Used to access the admin platform UI.
How to provide Platform cert files? 1 1 = file paths on this server; 2 = paste PEM content.
Path to Platform certificate (.crt / .pem) — Full path, e.g. /etc/ssl/certs/platform.crt. File must be a valid PEM with a -----BEGIN header.
Path to Platform private key (.key / .pem) — Full path, e.g. /etc/ssl/private/platform.key. Must match the certificate (installer validates before proceeding).
Path to Platform CA / intermediate bundle (.pem) — Full path to your CA chain bundle. Provided by your CA alongside the certificate.
Use same cert files for Recipient? yes Enter yes if using a wildcard or SAN certificate that covers both domains. Enter no to provide separate files for the Recipient domain.
Cert / key validation The installer validates that the certificate and private key moduli match using openssl before building the full-chain or touching Nginx. If they do not match, both files are removed and the installer exits — re-run with the correct matching pair.

Paste mode (option 2)

When pasting PEM content, type or paste each block, then press Enter, type EOF, and press Enter again to finish each file.

# Example: pasting a certificate
-----BEGIN CERTIFICATE-----
MIIFazCCA1OgAwIBAgIRA...
... (certificate content) ...
-----END CERTIFICATE-----
EOF           # ← type this, then press Enter
7

Post-Install Verification

Once the installer completes, verify the stack is running correctly:

# Check all containers are running
cd /opt/gosecureshare
sudo docker compose ps

# Check API health
curl -s http://127.0.0.1:8181/healthz
curl -s http://127.0.0.1:8282/api/health/ping

# View logs if something is wrong
sudo docker compose logs --tail=100 api_platform
sudo docker compose logs --tail=100 api_recipient
sudo docker compose logs --tail=100 db-migrate

All containers should show Up status. The health endpoints return 200 OK when the services are ready.

Access URLs after install

ServiceURLNotes
Platform (Admin UI) https://platform.example.com:8443 Non-standard HTTPS port in SSL Mode 2. Log in with the admin email and password entered during install.
Recipient (Share UI) https://share.example.com Standard HTTPS port 443. This is the URL shared with secret recipients.

To upgrade later

# Run the upgrade helper on the production server
cd /opt/gosecureshare
sudo ./upgrade.sh
Never use git pull on the production server Always upgrade via upgrade.sh or by re-running install.sh with GSS_FORCE_REINSTALL=true. Direct git operations on the server are not supported.
